# Changelog

All notable changes to rails-ui-kit are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/), and this project follows semantic versioning per [`RELEASING.md`](./RELEASING.md).

## [Unreleased]

## [0.3.0] - 2026-09-15

This release rebuilds the kit on a shared foundation — design tokens, a component base, and four Stimulus primitives — and moves every existing component onto it. It then sets a bar for what the kit ships: a component either owns a Rails or Turbo concept, or solves something genuinely hard in the browser. Sixteen components built during this cycle were deleted against that bar before ever being released; none of them existed in 0.2.0, so nothing you use goes away. `Ui::SelectComponent` is the first component built to it.

**Upgrading from 0.2.0 is a breaking change.** [`UPGRADING.md`](./UPGRADING.md) covers it: five things to fix, the hand-written markup changes, and a grep checklist. Ruby 3.2, Rails 7.2 and Tailwind CSS 4 are new floors.

### Added
- Design tokens in `app/assets/tailwind/rails_ui_kit/engine.css` — shadcn/ui's CSS-variable names verbatim with Product Matter's own `oklch()` values, defined under `:root` and redefined under `.dark`, and mapped through `@theme inline` so `bg-primary`, `text-muted-foreground`, `border-border`, `ring-ring` and their siblings compile. A host app reskins the kit by redefining the same variable names after the import; an external shadcn theme drops in unchanged. `--radius` drives the `rounded-*` scale and resolves to Tailwind's own defaults at its shipped value, so no existing component's radius changes.
- `Ui::Base` — the shared component foundation. A class-level `class_variants` declaration wraps `ClassVariants.build`, and the resolved classes are merged through a single process-wide `TailwindMerge::Merger` with the caller's `class:` merged last, so a caller's utility replaces a conflicting variant default instead of racing it in stylesheet order. Also carries generic HTML attribute forwarding (`data:`/`aria:` hashes merge by key) and the `data-slot` styling hook.
- `Ui::ButtonComponent` — six variants (`default`, `destructive`, `outline`, `secondary`, `ghost`, `link`) across four sizes (`default`, `sm`, `lg`, `icon`). Renders a `<button>`, or an `<a>` when given `href:`. Token-backed focus-visible ring, disabled styling for both element forms, and automatic sizing for an unsized inline `<svg>` child. A disabled `href` button drops its href and reports `role="link" aria-disabled="true"`, so it is inert without JavaScript.
- Three presentational components, each on `Ui::Base` with a unit test, a browser test that runs axe and measures contrast on every token surface in both modes, and a docs page:
  - **Form controls:** `Ui::InputComponent`, `Ui::LabelComponent`, `Ui::TextareaComponent`. Invalid and disabled states come from `aria-invalid` and `disabled` on the element rather than Ruby keywords, so form binding can set them later. Label dims from CSS when its control is disabled.
- `Ui::FieldComponent`, which wires a label, control, description and error into one accessible unit. The caller writes no ids: the control's `id`, the label's `for` and an `aria-describedby` naming only the parts that actually render are all derived from the field's `name`, using Rails' own id derivation so it matches what `form_with` emits. Errors set `aria-invalid` on the control and `data-invalid` on the wrapper, and styling keys off those attributes rather than DOM structure, so Rails' `field_error_proc` wrapper can't break it. It accepts Input, Textarea, Select or a custom control.
- A model-bound Field infers its enum. `Ui::FieldComponent.new(model: @order, attribute: :status)` with a Select or Choices control and no options given reads the enum from the record's class, and a control given `enum:` without `model:` takes the class from the field. Select and Choices also accept a bound record for `model:`, not only a class, so the natural line no longer raises. A source you state yourself is never overridden.
- `@floating-ui/dom` is vendored into the gem as one self-contained module and pinned locally, with its MIT licence alongside. The jsDelivr pin it replaces looked like one dependency but re-imported two more from the CDN by URL, so with jsDelivr unreachable a host lost Turbo, Stimulus and every controller on the page, not only positioning. The three transitive pins are gone with it.
- `Ui::ChoicesComponent` — a radio group (`multiple: false`) or checkbox group (`multiple: true`) over real inputs, in a list or card appearance, built from a collection, array, hash or model enum. It renders the names, ids, values and hidden empty field that `collection_radio_buttons` and `collection_check_boxes` render, so unchecking every box clears the association instead of silently keeping the old values. The group is a `<fieldset>` named, described and marked invalid through Field. Arrow keys, Space, single selection, `required` on radios, form reset and the checked, focus and disabled styling are all the platform's and CSS's. Choices page in the `examples/` docs app.
  - Three deliberate departures from Rails, each to prevent losing data: `[]` is appended to a stated name; a value that is both checked and locked is carried by a hidden input, so saving never deletes what the form showed as checked; and a disabled group disables its hidden fields too, where Rails' collection helpers leave theirs enabled and wipe the association. **A locked checkbox is not authorization** — a hidden input can be edited in the browser, so the server still decides.
  - `ui--choices` is the only JavaScript, attached solely when a checkbox group is both `multiple:` and `required:`, because no browser has an "at least one checked" constraint. Its message comes from `rails_ui_kit.choices.required_message`, overridable per instance.
- **Field built from a model.** `Ui::FieldComponent.new(model: @user, attribute: :email)` renders the whole field from the record: the same name and id `form_with` would emit, the label text `form.label` would show, the model's errors, and its current value — so a 422 re-render keeps what the user typed. Password and file inputs never get a value back. The field is marked required only when the model has a presence validator with no conditions; anything conditional (`if:`, `on:`, `allow_nil:`) is deliberately left unmarked, because a wrongly required field blocks a submission the model would have accepted, with no request and no log. Anything you pass explicitly wins over what the model says, which is the escape hatch for nested attributes and conditional validation. Works with any ActiveModel object; no ActiveRecord required.
- `required:` on Field sets native `required` on the control, `data-required` on the wrapper and a decorative `*` on the label that screen readers don't read, all from one value.
- **Help text gives way to the error.** An invalid field hides its description and shows the error in its place, and back again once it's valid. The description stays in `aria-describedby`, so screen reader users keep the guidance on how to fix it. When a Turbo morph delivers the change, the swap animates through `ui--presence` and the newly revealed error is announced; under reduced motion it swaps instantly. A full-page or frame render delivers a brand-new field with no previous state, so it appears without animation and without announcing every error on the page at once. The new `ui--field` controller is registered by `registerControllers`.
- Four shared Stimulus primitives, so a component stops carrying its own copy of behaviour the kit already knows how to do: `ui--presence` (the open, closing and closed lifecycle, waiting for a real animation to finish rather than guessing a duration), `ui--overlay` (the platform top layer, a reference-counted scroll lock so nested overlays can't unlock the page early, focus return and a cancelable dismiss), `ui--anchor` (one Floating UI wrapper publishing `data-side` and `data-align`, repositioning on scroll and resize), `ui--roving-focus` (arrow-key navigation with typeahead in both focus models: real focus for menus, `aria-activedescendant` for listboxes and comboboxes). Every component in the kit now sits on them: Modal, Confirm Dialog, Dropdown, Popover, Tooltip and Select share one implementation of each behaviour, and only `ui--anchor` imports Floating UI.
- `class_variants` and `tailwind_merge` as runtime dependencies.
- A browser test lane: `bundle exec rake test:system` builds the docs app's CSS, then drives the `examples/` app in headless Chrome, with `assert_accessible` running axe-core against the page or a selector. `bundle exec rake test` stays browser-free. CI runs the unit lane across Ruby 3.2–4.0 and the system lane once.
- A stress page and a shared invariant check. `/stress` in the `examples/` app renders the whole kit at once in a host-shaped layout — only what `rails_ui_kit:install` tells a host to render, so the docs layout can never again hide a missing controller — and its suite drives the components into each other under six condition profiles. `assert_kit_invariants` on `ApplicationSystemTestCase` checks nine things after any sequence (no scroll lock left behind, nothing orphaned in the top layer, focus on a real visible element, every `ui--*` controller still connected, no duplicate ids, a silent console, axe on the whole page, and more) and any suite can call it; a planted-fault self-test proves each invariant reports.
- An opt-in slow lane: `SLOW=1 bundle exec rake test:system` emulates network latency, so a test that reads a value before the response that changes it fails every run instead of only on a slow machine. It is never on by default, and no test reads the variable.
- Button page in the `examples/` docs app.
- `--destructive-foreground` design token in `app/assets/tailwind/rails_ui_kit/engine.css` — a kit extension beyond shadcn's token contract, since current shadcn has none. `Ui::ButtonComponent`'s destructive variant now sets its label from this token instead of `text-primary-foreground`, so the label no longer depends on `--primary-foreground`'s value.
- Kit parts default their border color to `--border`. Tailwind v4 draws a border with no color utility in `currentColor`, so a bare `border-t` on a kit part rendered near-black. The default is a base-layer rule scoped to `[data-slot]`, so any border color utility still wins and borders in host-app markup are unaffected.
- `Ui::SelectComponent` — a select built from a Rails collection, model enum, options array or hash, mirroring `collection_select` and `options_for_select` (including `prompt:`, `include_blank:`, grouped options and the blank option a `required` select gets). The real `<select>` is the only place the value lives, so the form submits it, `required` blocks submission, a form reset restores it, Turbo's page cache brings it back, and it still works with no JavaScript. Enhanced, it becomes a WAI-ARIA select-only combobox with the full keyboard model — typeahead, Home/End, PageUp/PageDown — while the select keeps the value and fires `input` and `change` as a native select would. On a touch screen it keeps the platform's own picker; `native_on_touch: false` opts out. Select page in the `examples/` docs app.
- `Ui::SelectComponent(search: true)` — the searchable form. Typing filters the list, ignoring case and accents, hides groups left empty, shows a "No results" state and announces the result count. Filtering is a view over the list only: the `<select>`'s options never change, and what you type is never turned into a choice. Escape on a closed field cancels, putting the text back to the current selection without touching the value — a deliberate departure from the ARIA example, which clears the field, because there the text *is* the value and here the select is. Clearing a choice is what a blank option is for.
- A shared control size scale. `Ui::InputComponent`, `Ui::SelectComponent` and `Ui::TextareaComponent` take `size:` — `:sm`, `:default` or `:lg`, the steps `Ui::ButtonComponent` has — and every control at a size reads its height from one token: `--control-height-sm`, `--control-height` or `--control-height-lg`, kit extensions in `engine.css`. A row of controls at one size lines up, and redefining a token retunes every control at that size, across the app or inside one element. Textarea's size sets its minimum height. Nothing changes at the defaults: every control, and Button at each of its four sizes, renders the size it did, including in an app that has retuned Tailwind's `--spacing`, and a browser test measures it. Keep control heights at 24px or more: below that a control fails WCAG 2.5.8's target size minimum, and the kit doesn't clamp a value you set. See Overriding in the README.
- `RailsUiKit::TestHelpers#ui_select` for host system tests. An enhanced Select lays its native `<select>` under the combobox, so Capybara's `select "…", from: "…"` no longer picks what a user would; `ui_select "Pending", from: "Status"` drives the widget the way a person does and falls back to the native select where the component isn't enhanced. `require "rails_ui_kit/test_helpers"` and include it. Nothing loads it at runtime.
- `ui--roving-focus`'s `pageStep` value (default `0`, off). When set, PageDown and PageUp move that many items and stop at the first or last, as the ARIA combobox pattern expects. It counts only items the arrow keys can reach, so disabled and hidden items don't inflate the jump.
- `Ui::FieldComponent` gives its label an id (`"<control id>-label"`), so a control that `<label for>` can't name — a `div` acting as a combobox, say — can point `aria-labelledby` at it.
- `ui--overlay`'s `moveFocus` value (default `true`). Setting it to `false` keeps focus where it is when a layer opens, as a hint already does, for a popup whose trigger must keep focus, such as a combobox's input.
- `Ui::ConfirmDialogComponent` is a template whose contents are yours. It renders no icon by default; an `icon` slot and a `body` slot carry content when you want it. `confirm_variant:` (default `:destructive`) picks the confirm button's Button variant — a "Publish post?" confirmation can say `:default` — and the same choice is reachable from `defaultConfirmDialog({ confirm_variant: })` and `data-turbo-confirm-confirm-variant`. Both buttons are `Ui::ButtonComponent`, so they inherit its tokens, dark mode and focus ring; the dialog sits on `Ui::Base` and the tokens, and its eight `*_class:` keywords now merge onto the defaults instead of replacing them.
- **Modal, Dropdown, Popover and Tooltip join `Ui::Base`**, so the kit has one foundation rather than two: `class:` merges through tailwind_merge on every component (Modal's `<dialog>`, the others' root), `data:` and `aria:` forward everywhere, every part carries `data-slot`, and the last palette literals are gone — Popover and Dropdown panels are `bg-popover`, Tooltip is `bg-foreground text-background`. Dropdown's panel now draws its own surface instead of showing the browser's default popover background through it.
- **Dropdown runs on `ui--overlay`** in layer mode, like Popover: it binds its own trigger (no more hand-written `click->ui--dropdown#toggle`), emits `ui--overlay:opened`, `:closed` and `:dismiss` like every other overlay, takes part in nested dismiss order, and no longer warns about a missing `ui--anchor` on every page load. `ui--overlay#closeNow` closes without the exit animation and still dispatches `closed`.
- Closed-set keywords fail loudly: an unknown `position:`, `kind:` (including the removed `:listbox`) or `placement:` raises in development and test and falls back with a log line in production; placements accept symbols. An undeclared `*_class:` or `*_classes:` keyword raises too, instead of quietly rendering as an HTML attribute — the trap that would otherwise have made every deprecated class keyword a silent no-op. `RailsUiKit.deprecator` registers with the host app so its warnings follow the host's deprecation settings.
- **Toast, rebuilt.** One payload — `type`, `title`, `description`, `actions`, `duration`, `icon` — renders identical markup whether it comes from a Ruby render, `turbo_stream.ui_toast`, or `window.triggerToast`; a test compares the three. Content given with no title becomes the description; a title stacks above it; actions go in a footer. `Ui::ToastContainerComponent.new(flash: flash)` turns Rails' `notice` and `alert` into toasts with no hand-wiring, plus a `toast` key for a full payload. Actions are `{ label:, href:, method:, variant:, class:, dismiss: }`, rendered through `Ui::ButtonComponent` so they inherit its tokens and focus ring; a non-GET `method:` renders a form the way `button_to` does, and an `href` must be relative or `http(s)` — anything else is rejected, loudly in development. A toast with an action never auto-dismisses unless the payload sets `duration`; every countdown pauses on hover, keyboard focus and a hidden tab, and shows no animated bar under reduced motion. F8 moves focus to the newest toast's first action and Escape closes it and returns focus. Six status tokens (`--success`, `--warning`, `--info` and their foregrounds) join the kit extensions, each meeting contrast on the surfaces a toast sits on. Toast and its container sit on `Ui::Base`.
- **Modal and Turbo, as a lifecycle.** `turbo_stream.ui_close_modal` closes the kit modal from a server response, through its own exit animation, skipping the unsaved-changes prompt; it does nothing when no modal is open. `ui--modal#closeOnSuccess`, bound to `turbo:submit-end`, closes on a 2xx whose response renders nothing. The whole flow — open from a stream, swap an inner frame, answer an invalid form with a 422, close from the server — is on a Modal & Turbo docs page backed by real routes and controller actions.
- `docs/guides/modal-and-turbo.md` and `docs/guides/forms.md` ship inside the gem. Every code sample in each is an exact slice of a demo file, and a test fails if one drifts or the guide stops being packaged.
- `rails g rails_ui_kit:agent_skill`, opt-in. It writes a skill and one `AGENTS.md` line that point a host's agents at the guides in the installed gem, never copying them, so upgrading the gem can't leave stale instructions in the host.
- Translations. Every user-visible string the kit renders, including accessible names such as a toast's close button, now lives in `config/locales/rails_ui_kit.en.yml` under `rails_ui_kit.*`. The engine loads that file automatically, and a host overrides any key from its own locale files. Components that own a Stimulus controller render their translated strings into data attributes for the controller to read, so JavaScript never keeps a second, English-only copy. Hand-written markup that leaves those attributes out still falls back to English. No component renders two of these strings, the `ui--dark-mode` toggle labels and the Turbo disable-with meta tag, so the host writes that markup itself using the shipped keys. Internationalization page in the `examples/` docs app.

### Fixed
- A Turbo morph — a 422 answered on a page that refreshes with morphing, or a morph refresh itself — broke two things it should have left alone: `ui--select` stopped enhancing, so every combobox on the page went back to hidden, and the morph stripped the `popover` attribute and ARIA that `ui--overlay` had written onto every layer, so the next open threw. Both controllers now keep what they wrote through a morph. Found by the stress page on its first run.
- A Turbo morph closed every open Dropdown, Popover and Select on the page — the server's markup carries no id for a panel, so the morph replaced the element and disconnected its controller — meaning a refresh another user triggered closed the menu this user was in. An open layer now survives a morph. A Modal is deliberately not covered: whether it survives is the host's decision, made with `data-turbo-permanent` on the layout's container, as the Modal + Turbo guide teaches.
- A Tooltip on an `aria-disabled` control never opened, because the kit's own Button sets `pointer-events: none` on it — the pattern the docs recommend. Hover is now tracked on the wrapper.
- A centred Modal sat half off-screen in a right-to-left document: `left-1/2` follows the inline start, so a 320px dialog landed at x = −160 with its controls unreachable. Centring is now direction-proof.
- Focus returned to the wrong place in two cases: after an outside click inside a Modal it was left on the `<dialog>` itself, and when one gesture closed a Dropdown by opening a Popover, the Popover recorded the Dropdown's trigger as its return target — Chrome restores popover focus before the click's own default action, so the restore now waits for it.
- `ui--turbo-disable-with` returns focus to a submit button that Turbo disabled during the request: Chrome drops focus off a disabled element, leaving keyboard users on `<body>` after every Turbo submit. Restored only when nothing else has claimed focus.
- The browser tests ran at 756×413 despite the registered 1400×1400 — `driven_by`'s `screen_size` was never applied, and 37 files carried a private resize to compensate. The base class now honours it (Chrome's frame accounted for, the no-JavaScript driver left alone); the private resizes are gone. Test-suite helpers copied across up to five files (`press`, `focused?`, `click_at`, the console and error captures, three divergent `ax_node`s) are one `test/support/browser_helpers.rb`; the byte-identical Input and Textarea contrast suites are one parameterised file; the whole lane runs as one process in 20m27s, of which the stress page is 14m00s.
- The documented Turbo Stream toast recipe, `turbo_stream.append "body"`, showed nothing: Turbo treats the target as an element id, so it matched nothing and failed silently. `turbo_stream.ui_toast` replaces it.
- A toast's `timeout` was written unchecked into an inline style, so a payload could inject CSS. `duration` is coerced to an integer and nothing from a payload reaches a style attribute.
- `rails_ui_kit:install` could corrupt a host's JavaScript: it injected at every match, so a second `@hotwired/stimulus` import produced a duplicate `registerControllers` import (a SyntaxError that disables every Stimulus controller), and a commented-out `Application.start()` got the registration inserted before the real one. It now injects once, after the first real match.
- `rails_ui_kit:install` replaces `stylesheet_link_tag :app` with the stylesheets it linked, by name. tailwindcss-rails' engine stub under `app/assets/builds/tailwind/` is a Tailwind input, not a stylesheet, and `:app` served it — the browser then requested its absolute `@import` path and logged a 500 with the gem's server path on every page load. The maintainers' guidance is to link `"tailwind"` by name; the upstream filter is unmerged.
- `rails_ui_kit:agent_skill` duplicated its `AGENTS.md` line on a second run when the host had no `AGENTS.md` before the first.
- `ui--turbo-disable-with` on a `data-turbo="false"` form dropped the clicked button's `name` and `value` from the POST (`decision=approve` never arrived), because it disabled the button inside the `submit` event, before the browser built the form data. It now disables on the next tick, leaves the buttons alone when a later listener cancels the submit, and restores them after Back from the browser's cache.
- `ui--turbo-disable-with` rebuilt the button through `innerHTML`, dropping listeners and controller state on its children and failing under Trusted Types. It restores the original nodes and builds its spinner as DOM.
- `ui--dark-mode` stored the preference under the generic `theme` key, so a host storing its own value there (`"system"`) was forced to light. The key is now `rails_ui_kit:theme`, with the old key read once as a fallback so saved preferences survive.
- On a fresh install the confirm dialog never worked: nothing put the `ui--dialog` controller on the page, so `window.defaultConfirmDialog` was undefined and both `data-turbo-confirm` and Modal's unsaved-changes prompt fell back to the browser's own `confirm()`. The docs app hid this by wrapping the component in its layout. The `<dialog>` now brings its own controller, so rendering the component is the whole setup, and several dialogs on one page share one set of globals instead of overwriting each other's.
- The confirm dialog's panel shrank to fit its text below the `sm` breakpoint — 199px wide on a phone for a short message — instead of filling the screen.
- `customConfirmDialog("1-delete")` threw before trying the id, because it was tried as a CSS selector first; and a confirmation whose dialog left the page mid-question never resolved, leaving the caller hanging. It now resolves `false`.
- The docs advised passing `role: "alert"` to a Field's error through the control, which would have made the input itself an alert. Field now handles the error's announcement itself.
- Select tells screen readers when it is required. The enhanced combobox — the element a screen reader actually meets — carries `aria-required="true"` in both select-only and search mode, rendered on the server and kept in step with the `<select>`'s own `required`.
- Opening a modal no longer shifts the page sideways. Locking the page hides the scrollbar, and the kit reserved that space with `scrollbar-gutter: stable` on the root — but the lock also takes `<body>` out of flow, and a fixed element's containing block includes the reserved gutter, so the body laid out one scrollbar wider than unlocked and everything centred moved half a scrollbar. The gutter is now always held as padding on the body. The browser test that claimed to cover this measured an element that is `hidden` until a demo opens, so it was comparing two empty rectangles; it now measures the laid-out page and refuses to pass if its reference has no size.
- `ui--overlay` keeps an `aria-controls` that the markup already carries, instead of overwriting it with the popup wrapper's id. A combobox can now point it at its listbox. When the trigger has none, the overlay still supplies one, so Dropdown, Popover and Tooltip are unchanged.
- Reopening an overlay while it is still animating closed now works. Closing it with Escape, a backdrop click or light dismiss left it marked open until the animation finished, so an `open()` in that window was ignored. For example, a tooltip dismissed with Escape stayed hidden if it was triggered again before its exit animation finished.
- `window.defaultConfirmDialog()` called with no arguments no longer overwrites the dialog's own title and message with hardcoded English. It used to replace whatever `Ui::ConfirmDialogComponent` had rendered, including a caller's `title:`/`message:`, with "Confirmation required" and "Are you sure?".
- A modal with unsaved changes can no longer be closed without being asked. The overlay used to veto Escape through the browser's native dialog cancel event, which Chrome only makes cancelable when there has been fresh user interaction — so typing, pressing Escape, declining the prompt and pressing Escape again discarded the form silently. Escape is now taken as a keydown on the overlay's content and prevented there, while still standing aside for a tooltip or a genuinely higher layer that owns the key.
- Reopening an overlay from its own close callback no longer leaves an invisible modal dialog making the page unclickable, and focus is no longer returned to an element inside content that has just closed.
- Focus stays inside an open overlay when a Turbo Stream or frame swap removes the element that had it, and `[autofocus]` in the newly rendered content is honoured.
- `Ui::ModalComponent` no longer leaves an invisible backdrop that blocks every click after it closes. Closing removed markup only when the modal sat inside a turbo-frame, and then emptied that whole frame; it now removes the modal's own element wherever it is, and leaves the rest of a frame alone.
- `ui--modal` releases the scroll lock and restores focus however the modal leaves the page, including a Turbo Stream emptying or replacing its container.
- `ui--modal` and `ui--dialog` survive Turbo's page cache. Pressing Back used to restore a non-modal `<dialog open>`: `showModal()` threw, the stale backdrop blocked clicks, and every later confirm failed until a reload. Both now return to a closed state on `turbo:before-cache`, and never call `showModal()` on a dialog that is already open.
- `ui--modal`'s unsaved-changes guard falls back to the browser's `confirm()` when the kit's confirm dialog is missing or fails, instead of trapping the user in the modal.
- `ui--modal` moves focus to the dialog when an in-modal turbo-frame swap removes the focused element, rather than dropping it to `<body>`.
- `Ui::ConfirmDialogComponent` works under a Content Security Policy that blocks inline scripts. Its buttons were inline `onclick` handlers; they are now submit buttons in a `<form method="dialog">`.
- `Ui::ConfirmDialogComponent` focuses Cancel when it opens, so Enter no longer carries out a destructive action, and its keyboard order now matches its visual order.
- `Ui::ConfirmDialogComponent` is announced as an `alertdialog` with its message as the description, and Cancel shows a visible focus indicator.
- `ui--tooltip` describes the caller's control for screen readers. `aria-describedby` was set on the wrapper `<div>`, so the tooltip was never announced; it is now appended to the control's existing `aria-describedby` and removed on disconnect.
- `ui--tooltip` meets WCAG 1.4.13. Escape dismisses a visible tooltip without moving focus or closing a surrounding dialog; the pointer can move onto the tooltip without it hiding; and it stays visible while its trigger has focus, tracking hover and focus separately.
- `ui--tooltip` positions against and listens to the control rather than the wrapper, so in a block layout it no longer centres on the whole row or shows when hovering empty space beside the control.
- `ui--tooltip` hides on `turbo:before-cache`, so Back never restores a visible tooltip, and a quick leave-then-enter no longer leaves it hidden while hovered.
- `ui--dropdown` menus are fully keyboard-operable, following the WAI-ARIA menu button pattern. ArrowDown or ArrowUp on the trigger opens the menu on its first or last item; arrows move and wrap, Home and End jump to the ends, typing jumps to a matching item, Enter or Space chooses one, and the trigger stays the only Tab stop. Menus written with plain `<a>` or `<button>` items and no roles now work too: their items get `role="menuitem"`, where before focus stayed on the trigger and ArrowDown scrolled the page. `aria-disabled` items stay focusable but can't be chosen, and a disabled link never navigates.
- Opening a `ui--dropdown` or `ui--popover` closes any other that is open. `toggle()` called `stopPropagation()`, which hid the click from the other instances' outside-click listeners.
- Choosing a `menuitem` closes its `ui--dropdown`.
- `ui--dropdown` and `ui--popover` position against the caller's control rather than the wrapper `<div>`, so `*-end` placements and `match_width` are correct in block layouts, where the wrapper spans the full width. Clicking empty space beside a popover's button no longer toggles it, and the popover no longer cancels the default action of other clicks in its trigger slot.
- `ui--popover` puts `aria-haspopup="dialog"`, `aria-controls` and `aria-expanded` on the caller's control and returns focus there on Escape, matching the Dropdown fix.
- `ui--dropdown` and `ui--popover` return to a closed state on connect, disconnect and `turbo:before-cache`, and ignore a stored open value until connected. Pressing Back after using a menu no longer reopens it and pulls focus into it.
- `ui--dropdown` closes when Tab or focus leaves the menu. Escape closes an open dropdown or popover only when focus is inside it, on its trigger, or on `<body>`, and it respects `isComposing` and `defaultPrevented`, so it no longer pulls focus back from elsewhere on the page.
- `ui--dropdown` with `kind: :dialog` moves focus into its content when it opens.
- A fast close-then-reopen of `ui--dropdown` or `ui--popover` ends in a consistent state: pending timers and animation frames are cancelled.
- `Ui::Base` renders a boolean HTML attribute as absent when its value is a false-ish string. Rails treats any non-empty string as true, so `disabled: "false"` rendered a disabled control — a trap for form params and serialized values, which are strings. Covers `disabled`, `readonly`, `required`, `checked`, `selected`, `multiple`, `hidden` and `open`. `aria-*` and `data-*` values pass through verbatim, since `aria-invalid="false"` and a Stimulus `data-*="false"` are meaningful strings.
- `Ui::Base` keeps a component's own attributes when a caller passes `data: nil` or `aria: nil`, and normalises attribute keys so `"class"`, `"data-slot"`, flat `"data-foo"` and nested `data: { foo: }` can never render the same attribute twice with the wrong one winning.
- `Ui::Base` accepts Rails' conditional class forms, e.g. `class: ["a", { "b" => cond }]`, which previously rendered the hash as literal text.
- `Ui::Base` raises `Ui::Base::UnknownVariantError` for an undeclared variant value in development and test, instead of silently rendering a component with no background or size. In production it logs and falls back to the axis default, since variant values are often data-driven.
- `Ui::ButtonComponent` shows a focus indicator in forced-colors and Windows High Contrast mode. It used `outline-none` with a box-shadow ring, and forced-colors modes drop box-shadows, so focus was invisible. The outline-based ring also reaches at least 3:1 against every token surface in both modes; the old ring measured 1.5–2.2:1.
- `Ui::ButtonComponent`'s outline variant sets its own text colour, so its label can't disappear against a host's background.
- `Ui::ButtonComponent` accepts `variant: nil` and `size: nil` as the defaults rather than raising, leaves SVGs that the caller sized alone, no longer resizes nested SVGs, and handles `"disabled" => true` and `disabled: "false"` correctly.
- Toasts are announced reliably. `Ui::ToastContainerComponent` renders persistent, visually hidden live regions (a polite `status` and an assertive `alert` for errors) that exist before any toast arrives, and each toast writes its title and body into the matching region when it connects, whether triggered from JavaScript or rendered by the server. Previously each toast was inserted as its own live region with its text in the same DOM change, which screen readers often don't announce.
- Toasts pause their auto-dismiss timer, and its progress bar, while hovered or while focus is inside them, and resume with the time that was left (WCAG 2.2.1).
- `timeout: 0` keeps a toast open through `window.triggerToast` and the `rails-ui-kit:toast` event, as it already did for server-rendered toasts. JavaScript treated `0` as "use the default".
- `ui--turbo-disable-with` restores a submit button's real state. Turbo disables the submitter before `turbo:submit-start` fires, so the controller recorded "disabled" as the original state and put it back that way; any form still on the page after submitting, as with a Turbo Stream response, kept a dead submit button. A submitter is now known to have been enabled, while other elements keep their actual state, so a button an app disabled deliberately stays disabled.
- `ui--turbo-disable-with` restores every element it disabled on `turbo:before-cache`, so going Back after a submission no longer shows a button stuck on its disabled-with text.
- `ui--dark-mode` sets `aria-pressed` on its toggle, updates every toggle target rather than only the first, and no longer throws where `localStorage` is unavailable.
- `ui--dialog` settles each confirm only from its own open and close. `dialog.close()` queues its `close` event, so closing a confirm and reopening it straight away let the first cycle's event answer the second prompt; a Cancel could resolve the next confirm. Pending confirms also settle synchronously on `turbo:before-cache`.
- `ui--turbo-confirm` reads `data-turbo-confirm-title` from forms and from `link_to … data: { turbo_method: }` links, not only from submit buttons.
- `rails_ui_kit:install` writes a CSS import that resolves. It previously wrote `@import "../../app/assets/builds/tailwind/rails_ui_kit.css"` into `app/assets/tailwind/application.css`, which points at `app/app/assets/…` and fails the host's Tailwind build; it now writes `@import "../builds/tailwind/rails_ui_kit.css"`, where `tailwindcss:engines` puts the artifact. README corrected to match.
- `rails_ui_kit:install` registers controllers where Stimulus's `application` is in scope. On a default `rails new` importmap app, `application` lives in `app/javascript/controllers/application.js`, so appending `registerControllers(application)` to `application.js` threw `ReferenceError` and registered nothing. The generator now inserts the call after `Application.start()` in whichever file has it, and skips with a message when it finds neither.
- `ui--dropdown` puts `aria-haspopup` and `aria-expanded` on the caller's trigger control — normally a `<button>` — instead of the wrapper `<div>` the component renders around it, and returns focus to that control on Escape. A `<div>` is neither focusable nor announced with state, so a screen reader previously got no indication that a menu existed or was open, and closing with Escape dropped focus to `<body>`. No markup changes; the component resolves the first focusable element inside the trigger slot and falls back to the wrapper when there is none.

### Removed
- `Ui::DropdownComponent(kind: :listbox)`. It had no real selection model and moved focus onto `[role="option"]` elements, which a listbox must never do. Use `Ui::SelectComponent` instead. Dropdown keeps `:menu` and `:dialog`.

### Changed
- Deprecated, merged for one release and removed in 0.4.0: Modal's `max_width:` (use `class:`; merged, it can no longer narrow a modal above `sm` on its own, since the default `sm:` width still applies — pass the `sm:` classes), Popover's `panel_classes:` and Dropdown's `content_classes:` (use `with_panel(class:)`), and Dropdown's `with_menu` (use `with_panel`; `content` is reserved by ViewComponent). `ui--modal`'s prompt values are `unsavedChangesTitle`/`unsavedChangesMessage`, named after their locale keys; neither existed in 0.2.0.
- A toast's plain message is now its **description**, not its title; `{ title: "…" }` keeps the old look. `body:` is `description:` and `timeout:` is `duration:` — the old keys raise in development naming the new one, and still work with a warning in production. A message is looked up in I18n only when given as a Symbol; a String is always text (`"date"` used to render blank because it matched a key). An unknown `type:` raises in development and falls back to `info` in production. `notice` renders in the success colour rather than amber, since it is Rails' "it worked" key; `type: :warning` is the new amber. UPGRADING §6–7.
- The `ui--media-query` primitive is gone. A component that swaps on a media query now carries the query in its own CSS, where the browser applies it live and keeps applying it: on a coarse pointer Select hides its combobox and hands the box back to the native select, swapping the moment a pointer changes, with JavaScript flipping only what CSS can't — the accessibility tree and the tab order. It was never in a release, so there is nothing to migrate.
- **Minimum Rails is 7.2**, up from a declared 7.0 that never actually worked — `turbo-rails` and `view_component` already required 7.1. The suite passes on Rails 7.2 with no changes. Rails 7.2 and 8.0 raise `unknown keyword: quirks_mode` from their own JSON encoder when paired with version 3 of the `json` gem; that breaks any app on those versions, not just the kit, and is fixed in Rails 8.1.
- `Ui::ModalComponent`'s surface uses the `--background` and `--foreground` tokens instead of `bg-white dark:bg-gray-900`, so a modal matches the rest of a token-themed page. In dark mode its background changes from Tailwind's cool `gray-900` to the kit's dark background.
- **Form controls are identifiable.** `--input` is now a mid grey rather than a hairline: control boundaries measure 3.3–3.7:1 in light and 5.3–6.8:1 in dark, against 1.3–1.6:1 before, which is what WCAG 1.4.11 asks of a control's boundary. Control borders, including Button's outline variant, are visibly more present than before.
- **Destructive text is legible in dark mode.** Dark `--destructive` lightens to `oklch(0.71 0.14 27)` with a dark `--destructive-foreground`, the same treatment `--primary` already gets. Red text on dark surfaces goes from 3.2–3.5:1 to 5.4–6.9:1, so a danger message no longer has to avoid the colour that names it. Dark destructive buttons are a lighter red with a dark label.
- **A dark control's fill comes from a surface token**, `dark:bg-muted/50`, never from `--input`, which is reserved for boundaries. A translucent fill takes the tint of whatever surface it sits on, so controls match a host's page instead of clashing with it.
- Floating UI is pinned once, as a single bundled ESM build, instead of four hand-maintained pins for `@floating-ui/dom`, `core`, `utils` and `utils/dom`. Overriding only the `dom` pin in a host app used to leave a mismatched dependency graph that failed at runtime.
- **Dropdown, Popover and Tooltip now run on the shared `ui--anchor` controller**, so Floating UI is imported once in the kit instead of three times, and positioning, flipping and repositioning on scroll behave identically everywhere. Popover and Tooltip also move to `ui--overlay` for showing, hiding and dismissal, and Dropdown's menu keyboard model moves to `ui--roving-focus`. **If your app hand-writes these components' internals rather than rendering them:** the positioning attributes moved onto `ui--anchor` (`data-ui--anchor-placement-value`, `-offset-value`, `-match-width-value`), and `data-ui--popover-open-value` is gone. Dropdown forwards its old attribute names with a console warning for one release — but only on markup that already carries `ui--anchor`, so 0.2.0 markup still has to be rewritten; Popover and Tooltip forward nothing. UPGRADING §2 has the full before-and-after markup for all four overlays.
- A toast that can't find a live region now warns that it will not be announced to screen readers, and says to render `Ui::ToastContainerComponent` rather than hand-rolled container markup. It warns once per container, not once per toast, and the toast still renders and dismisses normally. This is the failure a real app hit: visible toasts, nothing announced, no error anywhere.
- Dropdown, Popover and Tooltip now warn in the console when a primitive they depend on (`ui--overlay`, `ui--anchor` or `ui--roving-focus`) is missing from the element's `data-controller`. Each missing primitive warns once per element and names what stops working. Markup copied from before the move onto the primitives used to open with no positioning or keyboard navigation and give no hint why. The components still fail soft rather than throwing.
- Escape now closes an open Popover from anywhere on the page, not only when focus is inside it. It renders in the browser's top layer, which gives Escape to the topmost layer wherever focus sits. It still never pulls focus back to the trigger when focus had moved elsewhere.
- **Modal and ConfirmDialog now run on the shared `ui--overlay` and `ui--presence` controllers**, so the kit has one implementation of the top layer, the scroll lock, focus handling and exit animation instead of one per component. ConfirmDialog gained a scroll lock it never had. **If your app hand-writes the Modal's internals rather than rendering the component, several attributes moved:** `data-ui--modal-target="dialog"` is now `data-ui--overlay-target="content"`, the backdrop `<div>` is gone in favour of the browser's own dialog backdrop, the `z-[60]`/`z-[61]` literals are gone, `data-ui--modal-position-value` is gone, and the `modal-*-visible` classes are now `modal-*-hidden`. The `closeOnBackdropClick` and `closeOnEscape` actions are gone; `close()` remains.
- `ui--overlay:dismiss` carries `detail.reason` — `escape`, `outside` or `programmatic` — so a host can veto one gesture without vetoing the others.
- **A host app's theme now always wins.** The kit's token values sit in `@layer theme.rails-ui-kit`, a sub-layer of Tailwind's lowest layer, so a host's own `:root`, `.dark`, `@layer base` or `@theme` definitions override them wherever they sit relative to the kit's import. Only one of those six arrangements used to win.
- **Dark mode's primary is lighter, with a dark label.** `Ui::ButtonComponent`'s `link` variant draws its text from `--primary`, and no single value can be dark enough to carry a white button label and light enough to read as text on a dark surface. Dark `--primary` is now `oklch(0.7 0.12 277)` with a dark `--primary-foreground`, mirrored to `--ring` and the sidebar primaries. Dark link text goes from 3.0–3.8:1 to 4.7–7.0:1, and the primary button's own label from 4.75 to 6.66. Light mode is unchanged.
- **The kit requires Tailwind CSS 4** via `tailwindcss-rails`. The Tailwind 3 and Sprockets instructions are removed; the tokens never reached those setups.
- `rails_ui_kit:install` writes `@custom-variant dark (&:where(.dark, .dark *));` into the host's CSS so `dark:` utilities and the tokens agree on what dark means, skipping with a warning when the host already defines its own.
- The Button docs page explains how to override a default that carries a modifier: pass the same modifier, e.g. `has-[>svg]:px-2`.
- `Ui::ToastComponent`'s visible element no longer carries `role` or `aria-live`; announcements go through the container's live regions, so a toast rendered outside `Ui::ToastContainerComponent` is not announced.
- The dark mode docs page documents an inline `<head>` script, rendered with a CSP nonce, that applies `.dark` before first paint so pages don't flash the wrong theme.
- `Ui::DropdownComponent` accepts `label:`, rendered as `aria-label` on its content, so a `kind: :dialog` dropdown can be named.
- `Ui::PopoverComponent` no longer binds `click->ui--popover#toggle` on its wrapper; the controller toggles when the caller's control is clicked. Markup that also wires the action on its own button still toggles once.
- `Ui::ModalComponent` accepts `aria:`, applied to the `<dialog>`, so a modal can be named, e.g. `aria: { labelledby: "edit-title" }`.
- Opening a second confirm on a `Ui::ConfirmDialogComponent` that is already showing one supersedes it: the first resolves `false`. Previously one click answered both.
- A closed `Ui::ModalComponent` removes its element, so it cannot be reopened in place by calling `open()` again. Render it again to reopen.
- `Ui::ConfirmDialogComponent` renders Cancel before Confirm, and its default `footer_class`, `confirm_class` and `cancel_class` changed to match. Overrides that relied on `sm:flex-row-reverse` or on the old button margins will lay out differently. Its `*_class:` keywords now merge onto the token defaults rather than replacing them, so a class that conflicts with a default wins and the defaults you didn't mention stay; `icon_class:` is removed and raises, since there is no glyph to style — put your icon and its classes in the `icon` slot. See UPGRADING §4–5.
- Minimum Ruby is now 3.2. `tailwind_merge`, a runtime dependency, requires it.
- `README.md` component table now lists `Ui::PopoverComponent` and `Ui::TooltipComponent`, which shipped in 0.2.0 but were never added, alongside the new `Ui::ButtonComponent`. Added a design-tokens and class-merge section under Overriding.
