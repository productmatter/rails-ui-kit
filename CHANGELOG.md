# Changelog

All notable changes to rails-ui-kit are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/), and this project follows semantic versioning per [`RELEASING.md`](./RELEASING.md).

## [Unreleased]

### Added
- Design tokens in `app/assets/tailwind/rails_ui_kit/engine.css` — shadcn/ui's CSS-variable names verbatim with Product Matter's own `oklch()` values, defined under `:root` and redefined under `.dark`, and mapped through `@theme inline` so `bg-primary`, `text-muted-foreground`, `border-border`, `ring-ring` and their siblings compile. A host app reskins the kit by redefining the same variable names after the import; an external shadcn theme drops in unchanged. `--radius` drives the `rounded-*` scale and resolves to Tailwind's own defaults at its shipped value, so no existing component's radius changes.
- `Ui::Base` — the shared component foundation. A class-level `class_variants` declaration wraps `ClassVariants.build`, and the resolved classes are merged through a single process-wide `TailwindMerge::Merger` with the caller's `class:` merged last, so a caller's utility replaces a conflicting variant default instead of racing it in stylesheet order. Also carries generic HTML attribute forwarding (`data:`/`aria:` hashes merge by key) and the `data-slot` styling hook.
- `Ui::ButtonComponent` — six variants (`default`, `destructive`, `outline`, `secondary`, `ghost`, `link`) across four sizes (`default`, `sm`, `lg`, `icon`). Renders a `<button>`, or an `<a>` when given `href:`. Token-backed focus-visible ring, disabled styling for both element forms, and automatic sizing for an unsized inline `<svg>` child. A disabled `href` button drops its href and reports `role="link" aria-disabled="true"`, so it is inert without JavaScript.
- Ten presentational components, each on `Ui::Base` with a unit test, a browser test that runs axe and measures contrast on every token surface in both modes, and a docs page:
  - **Form controls:** `Ui::InputComponent`, `Ui::LabelComponent`, `Ui::TextareaComponent`. Invalid and disabled states come from `aria-invalid` and `disabled` on the element rather than Ruby keywords, so form binding can set them later. Label dims from CSS when its control is disabled.
  - **Feedback and status:** `Ui::BadgeComponent` (default, secondary, destructive and outline; renders `<a>` when given `href:`), `Ui::AlertComponent` (default and destructive, with icon, title and description parts; no live-region role unless the caller passes one), `Ui::SeparatorComponent` (horizontal and vertical, decorative by default).
  - **Layout and affordances:** `Ui::SkeletonComponent` (stops pulsing under reduced motion), `Ui::SpinnerComponent` (`role="status"` with a caller-supplied name), `Ui::KbdComponent` with `Ui::Kbd::GroupComponent` for chords, and `Ui::AspectRatioComponent`.
- Nine more presentational components, same conventions and the same two tests plus a docs page each: `Ui::TableComponent` (caption, header, body, footer, row, head and cell parts in a scroll container), `Ui::BreadcrumbComponent` (draws its own separators, marks the current page), `Ui::PaginationComponent` (renders `Ui::ButtonComponent` for its links), `Ui::ItemComponent` (media, title, description, actions, header, footer, plus group and separator), `Ui::EmptyComponent`, `Ui::AvatarComponent` (fallback initials layered under the image, no load-detection controller), `Ui::NativeSelectComponent`, `Ui::InputGroupComponent` (the group draws the boundary, focus ring and invalid state, not the control inside it), and `Ui::ButtonGroupComponent`.
- `class_variants` and `tailwind_merge` as runtime dependencies.
- A browser test lane: `bundle exec rake test:system` builds the docs app's CSS, then drives the `examples/` app in headless Chrome, with `assert_accessible` running axe-core against the page or a selector. `bundle exec rake test` stays browser-free. CI runs the unit lane across Ruby 3.2–4.0 and the system lane once.
- Button page in the `examples/` docs app.
- `Ui::CardComponent` — the kit's first compound component. Parts are component-backed slots, each a `Ui::Base` subclass under `Ui::Card::` (`HeaderComponent`, `TitleComponent`, `DescriptionComponent`, `ActionComponent`, `ContentComponent`, `FooterComponent`), so every part takes `class:` with tailwind_merge and forwards HTML attributes. `with_header` (holding `with_title`, `with_description`, `with_action`), `with_body` and `with_footer` always render in that order; a block that sets no parts renders straight into the card. The body slot is `with_body` because ViewComponent reserves `content`. Card page in the `examples/` docs app.
- `--destructive-foreground` design token in `app/assets/tailwind/rails_ui_kit/engine.css` — a kit extension beyond shadcn's token contract, since current shadcn has none. `Ui::ButtonComponent`'s destructive variant now sets its label from this token instead of `text-primary-foreground`, so the label no longer depends on `--primary-foreground`'s value.
- Kit parts default their border color to `--border`. Tailwind v4 draws a border with no color utility in `currentColor`, so a bare separator such as a card footer's `border-t` rendered near-black. The default is a base-layer rule scoped to `[data-slot]`, so any border color utility still wins and borders in host-app markup are unaffected.

### Fixed
- `Ui::ModalComponent` no longer leaves an invisible backdrop that blocks every click after it closes. Closing removed markup only when the modal sat inside a turbo-frame, and then emptied that whole frame; it now removes the modal's own element wherever it is, and leaves the rest of a frame alone.
- `ui--modal` releases the scroll lock and restores focus however the modal leaves the page, including a Turbo Stream emptying or replacing its container.
- `ui--modal` and `ui--dialog` survive Turbo's page cache. Pressing Back used to restore a non-modal `<dialog open>`: `showModal()` threw, the stale backdrop blocked clicks, and every later confirm failed until a reload. Both now return to a closed state on `turbo:before-cache`, and never call `showModal()` on a dialog that is already open.
- `ui--modal`'s unsaved-changes guard falls back to the browser's `confirm()` when the kit's confirm dialog is missing or fails, instead of trapping the user in the modal.
- `ui--modal` moves focus to the dialog when an in-modal turbo-frame swap removes the focused element, rather than dropping it to `<body>`.
- `Ui::ConfirmDialogComponent` works under a Content Security Policy that blocks inline scripts. Its buttons were inline `onclick` handlers; they are now submit buttons in a `<form method="dialog">`.
- `Ui::ConfirmDialogComponent` focuses Cancel when it opens, so Enter no longer carries out a destructive action, and its keyboard order now matches its visual order.
- `Ui::ConfirmDialogComponent` is announced as an `alertdialog` with its message as the description, and Cancel shows a visible focus indicator.
- `ui--tooltip` describes the caller's control for screen readers. `aria-describedby` was set on the wrapper `<div>`, so the tooltip was never announced; it is now appended to the control's existing `aria-describedby` and removed on disconnect.
- `ui--tooltip` meets WCAG 1.4.13. Escape dismisses a visible tooltip without moving focus or closing a surrounding dialog; the pointer can move onto the tooltip without it hiding; and it stays visible while its trigger has focus, tracking hover and focus separately.
- `ui--tooltip` positions against and listens to the control rather than the wrapper, so in a block layout it no longer centres on the whole row or shows when hovering empty space beside the control.
- `ui--tooltip` hides on `turbo:before-cache`, so Back never restores a visible tooltip, and a quick leave-then-enter no longer leaves it hidden while hovered.
- `ui--dropdown` menus are fully keyboard-operable, following the WAI-ARIA menu button pattern. ArrowDown or ArrowUp on the trigger opens the menu on its first or last item; arrows move and wrap, Home and End jump to the ends, typing jumps to a matching item, Enter or Space chooses one, and the trigger stays the only Tab stop. Menus written with plain `<a>` or `<button>` items and no roles now work too: their items get `role="menuitem"`, where before focus stayed on the trigger and ArrowDown scrolled the page. `aria-disabled` items stay focusable but can't be chosen, and a disabled link never navigates.
- Opening a `ui--dropdown` or `ui--popover` closes any other that is open. `toggle()` called `stopPropagation()`, which hid the click from the other instances' outside-click listeners.
- Choosing a `menuitem` closes its `ui--dropdown`.
- `ui--dropdown` and `ui--popover` position against the caller's control rather than the wrapper `<div>`, so `*-end` placements and `match_width` are correct in block layouts, where the wrapper spans the full width. Clicking empty space beside a popover's button no longer toggles it, and the popover no longer cancels the default action of other clicks in its trigger slot.
- `ui--popover` puts `aria-haspopup="dialog"`, `aria-controls` and `aria-expanded` on the caller's control and returns focus there on Escape, matching the Dropdown fix.
- `ui--dropdown` and `ui--popover` return to a closed state on connect, disconnect and `turbo:before-cache`, and ignore a stored open value until connected. Pressing Back after using a menu no longer reopens it and pulls focus into it.
- `ui--dropdown` closes when Tab or focus leaves the menu. Escape closes an open dropdown or popover only when focus is inside it, on its trigger, or on `<body>`, and it respects `isComposing` and `defaultPrevented`, so it no longer pulls focus back from elsewhere on the page.
- `ui--dropdown` with `kind: :dialog` moves focus into its content when it opens.
- A fast close-then-reopen of `ui--dropdown` or `ui--popover` ends in a consistent state: pending timers and animation frames are cancelled.
- `Ui::Base` renders a boolean HTML attribute as absent when its value is a false-ish string. Rails treats any non-empty string as true, so `disabled: "false"` rendered a disabled control — a trap for form params and serialized values, which are strings. Covers `disabled`, `readonly`, `required`, `checked`, `selected`, `multiple`, `hidden` and `open`. `aria-*` and `data-*` values pass through verbatim, since `aria-invalid="false"` and a Stimulus `data-*="false"` are meaningful strings.
- `Ui::Base` keeps a component's own attributes when a caller passes `data: nil` or `aria: nil`, and normalises attribute keys so `"class"`, `"data-slot"`, flat `"data-foo"` and nested `data: { foo: }` can never render the same attribute twice with the wrong one winning.
- `Ui::Base` accepts Rails' conditional class forms, e.g. `class: ["a", { "b" => cond }]`, which previously rendered the hash as literal text.
- `Ui::Base` raises `Ui::Base::UnknownVariantError` for an undeclared variant value in development and test, instead of silently rendering a component with no background or size. In production it logs and falls back to the axis default, since variant values are often data-driven.
- `Ui::ButtonComponent` shows a focus indicator in forced-colors and Windows High Contrast mode. It used `outline-none` with a box-shadow ring, and forced-colors modes drop box-shadows, so focus was invisible. The outline-based ring also reaches at least 3:1 against every token surface in both modes; the old ring measured 1.5–2.2:1.
- `Ui::ButtonComponent`'s outline variant sets its own text colour, so its label can't disappear against a host's background.
- `Ui::ButtonComponent` accepts `variant: nil` and `size: nil` as the defaults rather than raising, leaves SVGs that the caller sized alone, no longer resizes nested SVGs, and handles `"disabled" => true` and `disabled: "false"` correctly.
- `Ui::CardComponent` keeps a long unbroken title, such as an email address, inside the card instead of pushing the header action out of it. A title-only header no longer carries an empty second row, and an action-only header sizes to its content.
- Toasts are announced reliably. `Ui::ToastContainerComponent` renders persistent, visually hidden live regions (a polite `status` and an assertive `alert` for errors) that exist before any toast arrives, and each toast writes its title and body into the matching region when it connects, whether triggered from JavaScript or rendered by the server. Previously each toast was inserted as its own live region with its text in the same DOM change, which screen readers often don't announce.
- Toasts pause their auto-dismiss timer, and its progress bar, while hovered or while focus is inside them, and resume with the time that was left (WCAG 2.2.1).
- `timeout: 0` keeps a toast open through `window.triggerToast` and the `rails-ui-kit:toast` event, as it already did for server-rendered toasts. JavaScript treated `0` as "use the default".
- `ui--turbo-disable-with` restores a submit button's real state. Turbo disables the submitter before `turbo:submit-start` fires, so the controller recorded "disabled" as the original state and put it back that way; any form still on the page after submitting, as with a Turbo Stream response, kept a dead submit button. A submitter is now known to have been enabled, while other elements keep their actual state, so a button an app disabled deliberately stays disabled.
- `ui--turbo-disable-with` restores every element it disabled on `turbo:before-cache`, so going Back after a submission no longer shows a button stuck on its disabled-with text.
- `ui--dark-mode` sets `aria-pressed` on its toggle, updates every toggle target rather than only the first, and no longer throws where `localStorage` is unavailable.
- `ui--dialog` settles each confirm only from its own open and close. `dialog.close()` queues its `close` event, so closing a confirm and reopening it straight away let the first cycle's event answer the second prompt; a Cancel could resolve the next confirm. Pending confirms also settle synchronously on `turbo:before-cache`.
- `ui--turbo-confirm` reads `data-turbo-confirm-title` from forms and from `link_to … data: { turbo_method: }` links, not only from submit buttons.
- `rails_ui_kit:install` writes a CSS import that resolves. It previously wrote `@import "../../app/assets/builds/tailwind/rails_ui_kit.css"` into `app/assets/tailwind/application.css`, which points at `app/app/assets/…` and fails the host's Tailwind build; it now writes `@import "../builds/tailwind/rails_ui_kit.css"`, where `tailwindcss:engines` puts the artifact. README corrected to match.
- `rails_ui_kit:install` registers controllers where Stimulus's `application` is in scope. On a default `rails new` importmap app, `application` lives in `app/javascript/controllers/application.js`, so appending `registerControllers(application)` to `application.js` threw `ReferenceError` and registered nothing. The generator now inserts the call after `Application.start()` in whichever file has it, and skips with a message when it finds neither.
- `ui--dropdown` puts `aria-haspopup` and `aria-expanded` on the caller's trigger control — normally a `<button>` — instead of the wrapper `<div>` the component renders around it, and returns focus to that control on Escape. A `<div>` is neither focusable nor announced with state, so a screen reader previously got no indication that a menu existed or was open, and closing with Escape dropped focus to `<body>`. No markup changes; the component resolves the first focusable element inside the trigger slot and falls back to the wrapper when there is none.

### Changed
- `Ui::ModalComponent`'s surface uses the `--background` and `--foreground` tokens instead of `bg-white dark:bg-gray-900`, so a modal matches the rest of a token-themed page. In dark mode its background changes from Tailwind's cool `gray-900` to the kit's dark background.
- **Form controls are identifiable.** `--input` is now a mid grey rather than a hairline: control boundaries measure 3.3–3.7:1 in light and 5.3–6.8:1 in dark, against 1.3–1.6:1 before, which is what WCAG 1.4.11 asks of a control's boundary. Control borders, including Button's outline variant, are visibly more present than before.
- **Destructive text is legible in dark mode.** Dark `--destructive` lightens to `oklch(0.71 0.14 27)` with a dark `--destructive-foreground`, the same treatment `--primary` already gets. Red text on dark surfaces goes from 3.2–3.5:1 to 5.4–6.9:1, so a danger message no longer has to avoid the colour that names it. Dark destructive buttons are a lighter red with a dark label.
- **A dark control's fill comes from a surface token**, `dark:bg-muted/50`, never from `--input`, which is reserved for boundaries. A translucent fill takes the tint of whatever surface it sits on, so controls match a host's page instead of clashing with it.
- **A host app's theme now always wins.** The kit's token values sit in `@layer theme.rails-ui-kit`, a sub-layer of Tailwind's lowest layer, so a host's own `:root`, `.dark`, `@layer base` or `@theme` definitions override them wherever they sit relative to the kit's import. Only one of those six arrangements used to win.
- **Dark mode's primary is lighter, with a dark label.** `Ui::ButtonComponent`'s `link` variant draws its text from `--primary`, and no single value can be dark enough to carry a white button label and light enough to read as text on a dark surface. Dark `--primary` is now `oklch(0.7 0.12 277)` with a dark `--primary-foreground`, mirrored to `--ring` and the sidebar primaries. Dark link text goes from 3.0–3.8:1 to 4.7–7.0:1, and the primary button's own label from 4.75 to 6.66. Light mode is unchanged.
- **The kit requires Tailwind CSS 4** via `tailwindcss-rails`. The Tailwind 3 and Sprockets instructions are removed; the tokens never reached those setups.
- `rails_ui_kit:install` writes `@custom-variant dark (&:where(.dark, .dark *));` into the host's CSS so `dark:` utilities and the tokens agree on what dark means, skipping with a warning when the host already defines its own.
- The Button and Card docs pages explain how to override a default that carries a modifier: pass the same modifier, e.g. `has-[>svg]:px-2`.
- `Ui::ToastComponent`'s visible element no longer carries `role` or `aria-live`; announcements go through the container's live regions, so a toast rendered outside `Ui::ToastContainerComponent` is not announced.
- The dark mode docs page documents an inline `<head>` script, rendered with a CSP nonce, that applies `.dark` before first paint so pages don't flash the wrong theme.
- `Ui::DropdownComponent` accepts `label:`, rendered as `aria-label` on its content, so a `kind: :dialog` dropdown can be named.
- `Ui::PopoverComponent` no longer binds `click->ui--popover#toggle` on its wrapper; the controller toggles when the caller's control is clicked. Markup that also wires the action on its own button still toggles once.
- `Ui::ModalComponent` accepts `aria:`, applied to the `<dialog>`, so a modal can be named, e.g. `aria: { labelledby: "edit-title" }`.
- Opening a second confirm on a `Ui::ConfirmDialogComponent` that is already showing one supersedes it: the first resolves `false`. Previously one click answered both.
- A closed `Ui::ModalComponent` removes its element, so it cannot be reopened in place by calling `open()` again. Render it again to reopen.
- `Ui::ConfirmDialogComponent` renders Cancel before Confirm, and its default `footer_class`, `confirm_class` and `cancel_class` changed to match. Overrides that relied on `sm:flex-row-reverse` or on the old button margins will lay out differently.
- Minimum Ruby is now 3.2. `tailwind_merge`, a runtime dependency, requires it.
- `README.md` component table now lists `Ui::PopoverComponent` and `Ui::TooltipComponent`, which shipped in 0.2.0 but were never added, alongside the new `Ui::ButtonComponent`. Added a design-tokens and class-merge section under Overriding.

## [0.2.0] - 2026-06-04

### Added
- `Ui::TooltipComponent` with `ui--tooltip` controller — hover/focus-triggered text tooltip using Floating UI. Sets `role="tooltip"` and `aria-describedby` automatically. Supports all 12 Floating UI placements with auto-flip and shift middleware.
- `Ui::PopoverComponent` with `ui--popover` controller — click-triggered floating panel for rich HTML content. Click-outside and Escape-to-close. Manages `aria-expanded` and `aria-haspopup` on the trigger.
- `app/assets/tailwind/rails_ui_kit/engine.css` — Tailwind 4 entry point auto-discovered by `tailwindcss-rails` 4.x. Registers `@source` directives for the gem's component templates, Ruby class-list constants, and Stimulus controllers, and re-imports the modal transform-state classes. Consumers `@import` the build artifact (`app/assets/builds/tailwind/rails_ui_kit.css`) emitted by `tailwindcss:engines` instead of relying on a vendor-copy task.
- `RELEASING.md` documenting the release-and-tag procedure for this internal gem.
- `CHANGELOG.md` (this file).

### Removed
- `app/assets/stylesheets/rails_ui_kit/index.css`. Its `@import "rails_ui_kit/index"` entrypoint did not resolve under Tailwind 4's CLI; replaced by the `tailwindcss-rails` engine convention above.

### Changed
- `lib/rails_ui_kit/engine.rb` importmap initializer now guards on `defined?(Importmap::Engine)` instead of the bare `Importmap` constant, removing a boot-order race.
- `rails_ui_kit.gemspec` pins `view_component` to `>= 3.0, < 5.0` to prevent silent upgrades to an untested major version.
- `dialog_controller.js`, `toast_container_controller.js`, and `turbo_confirm_controller.js` now save and restore the global hooks they install (`window.defaultConfirmDialog`, `window.customConfirmDialog`, `window.triggerToast`, `Turbo.config.forms.confirm`) instead of unconditionally deleting or overwriting them. Multiple-instance and reconnect cases no longer leave the page with broken globals.
- `turbo_confirm_controller.js` now no-ops with a console warning when Turbo is not loaded, instead of throwing.

## [0.1.0] - 2026-05-01

Initial release. Internal gem; not published to RubyGems.

### Added
- `Ui::ModalComponent` with `ui--modal` controller — 8-position modal dialog, backdrop, form-change tracking, Turbo Frame integration.
- `Ui::DropdownComponent` with `ui--dropdown` controller — Floating-UI-positioned dropdown with keyboard navigation; menu, listbox, and dialog modes.
- `Ui::ConfirmDialogComponent` with `ui--dialog` controller — native `<dialog>` with a Promise-based API and global helpers (`window.defaultConfirmDialog`, `window.customConfirmDialog`).
- `Ui::ToastComponent` and `Ui::ToastContainerComponent` with `ui--toast` and `ui--toast-container` controllers — auto-dismissing notifications, client-side render from per-type `<template>` clones, custom-event and `window.triggerToast` triggers.
- Utility controllers: `ui--form-change` (dirty-form tracking), `ui--turbo-confirm` (Turbo confirm interception), `ui--turbo-disable-with` (form-element disable styles), `ui--dark-mode` (theme toggle with localStorage and OS-preference fallback).
- Importmap pins for `@floating-ui/dom` shipped via the engine.
- Component-level Minitest coverage via a dummy app under `test/dummy`.
- CI matrix on Ruby 3.1, 3.2, 3.3, 3.4, and 4.0.
